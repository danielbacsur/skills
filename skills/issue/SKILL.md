---
name: issue
description: Use whenever opening, editing or suggesting an issue.
---

Only open an issue as a to-do for work that is coming up later. If you're about to make the change yourself, skip the issue and go straight to a pull request, and don't open issues to report finished work, ask questions or keep notes.

Give it a plain, human-readable title that says what needs doing, in sentence case with no type prefix, scope or trailing period. Keep it between 50 and 70 characters, aiming for about 60 and never going past 80. If it doesn't fit, rephrase it instead of padding it out or cutting meaning.

Write the body as one to three plain paragraphs that explain why the work matters, what done looks like, and anything someone picking it up would need to know. Give each paragraph three to four sentences, about 300 characters, staying between 200 and 400. Don't use headings, checklists or templates.

Don't add a generated-by line yourself, and leave out everything else: no labels, assignees, milestones, or markers and tags tied to a specific tool or harness. The one exception is putting it on a project board when the factory skill asks for it.
